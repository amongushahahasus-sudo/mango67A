# ショップの商品ファイルと確認後の受け渡し

写真に加えて、コードなどが書かれたTXT・PDF・ZIPファイルを商品として登録できます。ファイル商品は1商品につき1点で、購入申請後に管理者が確認し、承認してからダウンロードできます。ファイルの内容やコードは商品一覧・プレビュー・購入申請中の画面には表示しません。

## 初回の追加設定

既存の `schema.sql` と `photo-shop.sql` を実行した同じSupabaseプロジェクトのSQL Editorで、[shop-files.sql](shop-files.sql) を実行してください。既存の写真、役割、購入履歴、練習データは保持します。以前の開発者設定をもう一度行う必要はありません。

初回設定SQLを再実行する場合も、この追加SQLを後から実行してください。さらに機能を追加するSQLがある場合は、その機能の案内どおりの順番で最後まで実行します。

適用前のアプリは、引き続き写真の閲覧・購入ができます。追加SQLを適用するとファイル商品の登録・確認・受け渡しを利用できるようになります。更新前のアプリ用RPCは写真専用のままで、ファイル商品の確認手順を省略して取得することはできません。

## 販売と受け渡し

1. 管理者が「商品管理」でファイル商品を登録し、公開します。1ファイルに複数のコードが書かれている場合、そのファイル全体が同じ購入者へ渡ります。
2. 利用者が商品を購入申請すると、在庫1点を確保し、価格分の仮想利益を利用済みとして確保します。原本ファイルはまだ取得できません。
3. 管理者が購入申請を確認し、承認すると購入者がファイルをダウンロードできます。
4. 却下した場合は、確保した仮想利益と在庫を戻します。購入申請の履歴は消しません。

承認済みの申請は、取り消して在庫へ戻せません。渡したコードを別の購入者へ再販売しないためです。購入者のアカウントが削除されても承認済みの在庫確保は残ります。削除済みアカウントの確認待ち申請は、管理者が却下して在庫を戻せます。

既存の写真商品は在庫制限なし・購入後すぐにダウンロードする仕組みを継続します。写真の購入済み原本や、販売終了した写真への購入者のアクセスも保持します。

## ファイルと権限

- TXT、PDF、ZIPの各ファイル、15 MiBまで対応します。プログラムとして実行したり、ZIPをアプリで自動展開したりはしません。
- `shop-files` は非公開のストレージです。`{商品UUID}/original.txt`、`original.pdf`、`original.zip` のいずれかで保存します。
- ファイル本文、保存先、コードを一般のカタログへ返しません。管理者または承認済みの本人だけが、認証付きのダウンロードを利用できます。
- 投稿済みの商品ファイルは変更・削除できません。中身を変更する場合は、新しい商品として登録します。購入済み商品が別のコードへ置き換わることを防ぎます。
- 公開、価格、タイトル、説明は管理者が変更できます。申請後の価格変更は申請時の価格を変えません。
- 購入申請、確認、在庫確保、返却はSQL側で処理します。一般利用者は役割や申請状態を直接書き換えられません。

## 仮想利益の範囲

写真の購入済み額に加え、確認待ち・承認済みのファイル申請額を利用済み額として数えます。却下済みのファイル申請額は含めません。練習口座の残高や版番号は、ショップ側で書き換えません。

FXの利益は端末で計算する練習データです。この追加機能は利益の改変をサーバーで証明するものではないため、実価値のあるギフトカードなどの受け渡しは管理者の確認後に行います。管理者の承認は自動的な不正検証を意味しません。購入履歴と利用者を確認し、実際に渡してよいものだけを承認してください。

## APIの互換性

新しいクライアントは `get_reward_shop`、`purchase_shop_product`、`save_shop_product`、`get_shop_product_download`、`review_shop_order` を使用します。旧 `get_photo_shop` は写真だけを返します。旧購入・ダウンロードAPIでファイル商品を指定すると拒否します。

`shop_reward_snapshot` と `shop_reward_wallet` は内部用で、一般利用者へ実行権限を与えません。後続の追加機能は公開 `get_reward_shop` の応答へ情報を追加できますが、ファイルの承認・原本取得の制約は保持してください。
